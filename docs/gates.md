# 関門の確認表

設計書「開発ロードマップ」の関門を、機械で測れる項目と人が確かめる項目に分ける。
関門を越えられなければ次の段階へ進まず、その段階で調整する。記録は下の「記録」に新しい順に足す。

## 関門1（M0 共通の技術検証の終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 3つの描画経路 | `pnpm e2e`（`e2e/render-paths.spec.ts`: WebGPU・`?webgl`・IWER の immersive-vr で天球の試作を描く） | 3経路ともエラー 0、画面が真っ黒でない |
| VR の描画経路を決める | 上の結果で WebGPURenderer の WebGL2 経路で XR が動くか | 動けば ADR-0001 を確定、動かなければ VR 版だけ WebGLRenderer にする ADR を書く |
| PC 60fps | `pnpm snap "/?debug&t=590" ride` の fps（天球の見どころ） | 58 以上 |
| Quest 3 72fps | 実機の Quest Browser で `?debug&t=590`（人） | 72 以上 |
| ガラスの見た目 | `dev/core.html` の6種の並びを人が見る | 3経路で同じ印象 |

## 関門2（M1 プレビズと垂直スライスの終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 13分を通して乗れる | `pnpm e2e`（`e2e/ride.spec.ts`: `?rate=60` で 780 秒を通し、写真の画面まで） | 緑 |

| 温室で誰も酔わない | 人が VR で乗る | 酔わない |

## 記録

### 2026-10-21 関門2（機械で測れる項目）— main 5c7f75d（S-25 統合の時点。部屋は仮の形と、まだ統合前の Blender の部屋）

| 条件 | 結果 | 合否 |
|---|---|---|
| 13分を通して乗れる | `e2e/ride.spec.ts`: PC 幅・スマートフォン幅で `?rate=60` の通し、全区間を通って写真3枚でライドフォトへ、コンソールエラー 0。音の時計（待ち列から普通に乗る）は速さ 0.9〜1.1、フレームとの差 0.05 秒未満。負荷平均 14.7 の12並列でも緑（S-25 のレビュー） | 合格 |
| 動きの上限 | `pnpm comfort`: 標準 違反 0（最大 速度 1.20/3、加速度 0.09/0.5、上下 0.24/0.6、回転 3.0/15）、穏やか 違反 0（上下 0.24/0.3、回転 3.0/7.5） | 合格 |
| 通しの動画に退屈な区間がない | 人が見る（`pnpm previz:render` と `pnpm snap ride`）。部屋が揃ってから | 未 |
| 温室で誰も酔わない | 人が VR で乗る。温室（S-20）が入ってから | 未 |

関門1 の残り: PC 60fps（天球の見どころ）は天球の部屋（S-22）の統合後に測る。Quest 3 の 72fps とガラスの見た目は人が確かめる（ADR-0010 の実機の確認項目）。
