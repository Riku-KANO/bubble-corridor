# 関門の確認表

設計書「開発ロードマップ」の関門を、機械で測れる項目と人が確かめる項目に分ける。
関門を越えられなければ次の段階へ進まず、その段階で調整する。記録は下の「記録」に新しい順に足す。

## 関門1（M0 共通の技術検証の終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 3つの描画経路 | `pnpm e2e`（`e2e/render-paths.spec.ts`: WebGPU・`?webgl`・IWER の immersive-vr で天球の試作を描く） | 3経路ともエラー 0、画面が真っ黒でない |
| VR の描画経路を決める | 上の結果で WebGPURenderer の WebGL2 経路で XR が動くか | 動けば ADR-0001 を確定、動かなければ VR 版だけ WebGLRenderer にする ADR を書く |
| PC 60fps | `pnpm snap "/?debug&t=590" ride` の fps（天球の見どころ） | 58 以上 |
| Quest 3 72fps | 実機の Quest Browser で `?debug&t=590`（人） | 72 以上 |
| ガラスの見た目 | `dev/core.html` の6種の並びを人が見る | 3経路で同じ印象 |

### 2026-10-21 部屋7つがそろった時点の通し（main 44fe7e9）

- `pnpm snap ride`（1280×720、ヘッドレスの Chrome、Apple M5 Pro、WebGPU、auto の品質）: 18 の見どころすべてで 56.7〜60.2 fps、コンソールエラー 0。最も重いのは温室の入口（1:04、描画呼び出し 107、三角形 845k、56.7 fps）と夜明けの岸（11:52、呼び出し 139）。一覧の画像は `.snaps/sheet/ride-2026-10-21.jpg`（git の管理外）。
- `pnpm e2e`（10件）: 13分の通し（PC 幅・スマートフォン幅）、音の時計、描画の経路、VR を含めて緑。
- **関門4（初回の読み込み 10MB 以下）の見込み**: 本番のビルドで JS 1.35MB・CSS 0.34MB・rail.json 0.1MB、待ち列と乗り場の部屋 7.02MB で約 9MB（書体は使う文字の分だけ）。ただし待ち列の間に温室（4.92MB）も先に読み込む（HOME_PLAN の keep）ので、待ち列の灯りが全部灯るまでの転送は約 14MB になり、上限を超える。温室を乗車の後に回すか、温室の glb（4.2MB）を減らす（S-29 で扱う）。ブラウザの転送量での実測は関門4の確認で。
