# 関門の確認表

設計書「開発ロードマップ」の関門を、機械で測れる項目と人が確かめる項目に分ける。
関門を越えられなければ次の段階へ進まず、その段階で調整する。記録は下の「記録」に新しい順に足す。

## 関門1（M0 共通の技術検証の終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 3つの描画経路 | `pnpm e2e`（`e2e/render-paths.spec.ts`: WebGPU・`?webgl`・IWER の immersive-vr で天球の試作を描く） | 3経路ともエラー 0、画面が真っ黒でない |
| VR の描画経路を決める | 上の結果で WebGPURenderer の WebGL2 経路で XR が動くか | 動けば ADR-0001 を確定、動かなければ VR 版だけ WebGLRenderer にする ADR を書く |
| PC 60fps | `pnpm snap "/?debug&t=590" ride` の fps（天球の見どころ） | 58 以上 |
| Quest 3 72fps | 実機の Quest Browser で `?debug&t=590`（人） | 72 以上 |
| ガラスの見た目 | `dev/core.html` の6種の並びを人が見る | 3経路で同じ印象 |

## 関門2（M1 プレビズと垂直スライスの終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 13分を通して乗れる | `pnpm e2e`（`e2e/ride.spec.ts`: `?rate=60` で 780 秒を通し、写真の画面まで） | 緑 |
| 動きの上限 | `pnpm comfort`（標準・穏やか） | 違反 0 |
| 通しの動画に退屈な区間がない | `pnpm snap` の通し撮影（各区間の見どころ）を人が見る | 退屈な区間なし |
| 温室で誰も酔わない | 人が VR で乗る | 酔わない |

## 関門3（M2 本編制作の終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 全環境で13分を通して乗れる | `pnpm e2e`（PC 幅・スマートフォン幅・IWER の VR） | 緑 |
| 分岐 | e2e で琥珀・瑠璃の両方を通す | 万華鏡が金・青に変わる |

## 関門4（M3 磨き込みの終わり）

| 条件 | 測り方 | 合格 |
|---|---|---|
| 性能の目標 | `?debug` と実機（PC・中位スマートフォン・Quest 3） | 設計書「性能の目標」をすべて満たす |
| 初回の読み込み 10MB 以下 | `pnpm build` の出力と、ブラウザの転送量 | 10MB 以下 |
| 酔いのテスト | 人 | 通過 |
