# 泡沫回廊 企画・設計書
2026-10-20 · @Riku KANO

## 概要
シャボン玉のようなガラスのゴンドラに乗り、5つのガラスの部屋を巡る約13分のライド型アトラクションです。操作はほとんど要らず、誰でも乗るだけで最後まで楽しめます。触れれば音と光で応える、という小さな参加の余地を残します。
一言ピッチ: ガラスの泡に乗って、ガラスの夢の中を通り抜ける13分間。
| 項目 | 内容 |
| ジャンル | ライド型アトラクション(レールに沿って進む体験) |
| 体験時間 | 約13分(1周)。途中の分岐で2周目の景色が変わる |
| 人数 | 1人 |
| 対応環境 | PCブラウザ、スマートフォン、タブレット、VRヘッドセットのブラウザ(WebXR) |
| 入力 | クリック、タップ、マウスやスマートフォンの傾きでの見回し、VRでは頭と手 |
| 公開 | Cloudflareで静的配信。サーバーなし |
| ターゲット | ゲームに慣れていない人も含めた全員。短い時間で「すごいものを見た」と人に話したくなる体験 |
| 言語 | 日本語と英語。公開時から両方に対応。英語のタイトルは「Utakata: A Ride Through Glass」 |

### 体験の核
1. 運ばれる心地よさ: 自分で歩かなくても、ゆっくり漂いながら景色が向こうからやってくる
2. 息をのむ瞬間: 部屋に入るたびに、ガラス越しに想像を超える空間が開ける
3. 触れると応える世界: 手を伸ばしたガラスが鳴り、光の波紋が広がる
4. 持ち帰れる記念: 降りた後、一番輝いた瞬間がガラス玉の写真として手元に残る

### 設計の柱
1. 何もしなくても完成している: 一切操作しなくても、13分間が一つの作品として成立する
2. 触れれば必ず応える: 操作したときは、どこに触れても音と光で必ず反応する。失敗はない
3. カメラの道筋が決まっていることを最大限に活かす: どこから見られるかが分かっているので、すべてのカットを映画のように作り込める
4. 誰も酔わせない: 速度、回転、上下の動きに厳しい上限を設け、VRでも快適に乗れる

### 案1「ビードロの向こう」との関係
同じガラスの世界観を、案1は「歩いて謎を解く」、案2は「運ばれて眺める」という逆の向きから味わう作品です。ガラスの材質、UIの曇り表現、音の仕組み、Blenderの自動化は共通部品として作り、別々のディレクトリにそれぞれ同じものを置いて使います。

## 体験の流れ
乗り場から降車まで、7つの区間を13分で進みます。朝から夜、そして夜明けへと時間が流れ、空間は広さと狭さを交互に繰り返しながら、第4室「星の天球」で頂点を迎えます。
[EMBED node/a43e420b-77c1: 乗車の時間軸 · 7区間と見どころ]
各部屋の見どころ(◆)はどれも部屋の時間の後半にあり、最も長い第4室で楽曲と演出の頂点を迎えます。

### 起伏の設計
1. 全体の弧: 期待(乗り場)→ 驚き(温室)→ 親密(雨の回廊)→ 遊び(万華鏡)→ 頂点(星の天球)→ 余韻(夜明けの岸)→ 記念(写真)
2. 広さの交互: 広い温室 → 狭い回廊 → 中くらいの万華鏡 → 最大の天球 → 開け放たれた岸。狭い場所の直後に広い場所を置き、開けた瞬間の驚きを大きくする
3. 光の流れ: 朝 → 雨の昼 → 虹色 → 夜 → 夜明け。最も暗い天球の後に最も明るい夜明けを置く
4. 部屋の中の波: どの部屋も「入って10秒以内に視界が開ける → 中盤で触れて遊ぶ → 終盤は静かになって次の膜へ近づく」の順に作る
5. 見せ場の位置: 各部屋の一番の見せ場は、部屋の時間の3分の2あたりに置く
6. 音楽の頂点: 楽曲は天球の中盤(開始から約10分)で最も盛り上がり、ここでライドフォトを撮る

### 分岐
- 雨の回廊の終わりで、琥珀と瑠璃の2つの扉が現れる。手を伸ばした方、または長く見つめた方へゴンドラが進む
- 選んだ扉によって、万華鏡の間が「金の万華鏡」と「青の万華鏡」に変わる
- 何もしなければ瑠璃の扉へ進む。どちらを選んでも長さは同じ
- 2周目は前回と違う扉が少し強く光り、もう一方を見たくなるよう誘う

## 各ルームの詳細
各部屋は「景観・流れ・見どころ・触れると・音」の5点で設計します。見どころの時刻は、乗車からの経過時間です。

### 乗り場「泡の発着場」(0:00〜1:00)
- 景観: 夜明け前の静かな円形のホール。天井から大小のガラスの泡が吊られ、ゆっくり回っている。奥には虹色の薄膜が張られた門がある
- 流れ: 水面から透明な泡のゴンドラが浮かび上がり、目の前に止まる。乗ると泡の殻が下から上へ閉じ、表面に虹色が走る。ゴンドラはゆっくり浮き上がり、膜の門へ向かう
- 見どころ: 泡が閉じた瞬間から、世界がずっと薄い泡越しに見えるようになる。視界の縁にはいつも、泡の内側のかすかな反射と虹色が残る
- 触れると: 吊られた泡が鳴る。乗る前のこの場所で「触れると応える」ことを自然に覚える
- 音: 静かな持続音と水音

### 第1室「朝露の温室」(1:00〜3:30)
- 景観: 鉄骨とガラスの巨大な温室。葉も花もつるもガラスでできていて、葉先にはガラスの露がついている。床一面に光の模様が揺れる
- 流れ: 膜を抜けると、高い位置から温室全体を見下ろす。ゆっくり下降し、植物の間を縫うように進む
- 見どころ(2:40頃): 人の背丈の何倍もあるガラスの花が、光を集めながら開く。直後、すべての露が一斉に落ちて床で鳴る
- 触れると: 葉に触れると露が落ちて鳴る。蕾に触れると少し早く咲く
- 音: 風鈴のような高い音、露の落ちる音

### 第2室「雨の回廊」(3:30〜6:00)
- 景観: 雫形の柱が並ぶ細長く天井の低い回廊。ガラスの屋根を雨が叩き、水が伝い落ちる。壁の向こうに、水の膜越しの街の灯りがにじむ
- 流れ: 温室の広さから一転して、狭い空間を進む
- 見どころ(5:10頃): 降っている雨粒が一粒ずつガラス玉に変わり、空中で止まる。ゴンドラは止まった雨粒の間をすり抜けていく
- 触れると: 止まった雨粒に触れると、澄んだ音を立てて弾け、虹色の輪を残す
- 分岐(5:50頃): 琥珀と瑠璃の2つの扉が現れる
- 音: 雨音とガラスを伝う水。雨が止まった瞬間にほぼ無音になり、その静けさを際立たせる

### 第3室「万華鏡の間」(6:00〜8:00)
- 景観: 鏡とプリズムでできた多面体の部屋。部屋そのものが巨大な万華鏡で、進むほど模様が変わる。金の万華鏡は琥珀と金色の暖かい光、青の万華鏡は瑠璃と水色の冷たい光
- 流れ: 部屋の中心をまっすぐゆっくり通り抜ける。周りの模様だけが回り続ける
- 見どころ(7:20頃): 散らばったガラス片が集まり、部屋全体に巨大な花の模様を描く
- 触れると: 触れた場所のガラス片の色が変わり、その色が模様全体に繰り返し広がる。自分が触れた跡が模様として残る
- 音: ここで初めてリズムが入る。触れた音は模様の繰り返しに合わせてこだまする

### 第4室「星の天球」(8:00〜11:00)
- 景観: 巨大なガラスの球体の内側に広がる夜空。星はすべて光を宿した小さなガラス玉。中心へ向かって、何層もの透明な球の殻が重なっている
- 流れ: 2秒間の暗闇の後、星が一つずつ灯る。ゴンドラは球の殻を何枚も通り抜けながら上昇し、殻を抜けるたびに一つの音が鳴る
- 見どころ(9:50頃): 中心にたどり着くと、周囲の星が線でつながり、ガラスの街の姿を描く(案1の街「ハリノ」と同じ形)。この瞬間にライドフォトを撮る
- 触れると: 星に触れると、近くの星と光の線でつながる。自分だけの星座を描け、それもライドフォトに写る
- 音: 楽曲の頂点

### 第5室「夜明けの岸」(11:00〜12:30)
- 景観: 天球の殻を抜けた先の、ガラスの砂浜と穏やかな水面
- 流れ: 水面すれすれをゆっくり進む
- 見どころ(11:50頃): 水平線から朝日が昇り、砂浜のガラスが一斉に金色に光る。遠くに最初の乗り場が見える
- 触れると: 水面に触れると波紋が広がり、光の模様が砂浜まで届く
- 音: 楽曲が穏やかに収まり、波の音が残る

### 降車「泡の発着場」(12:30〜13:00)
- 乗り場に戻ると、ホールは朝の光に変わっている
- 泡の殻が上から下へ開き、弾けずに水面へ溶けていく
- そのままライドフォトの画面へ移る

## インタラクション設計
操作は「見回す」「触れる」「選ぶ」の3つだけです。どれも任意で、しなくても体験は完成していますが、触れればどこでも必ず音と光で応え、その音はすべて楽曲と調和します。

### 操作の種類
| 操作 | PC | スマートフォン・タブレット | VR |
| 見回す | マウスのドラッグ(または移動) | 端末を傾ける(許可制)、またはドラッグ | 頭を動かす |
| 触れる | クリック | タップ | コントローラーか手を伸ばして触れる |
| 選ぶ(分岐) | 扉をクリック、または見つめる | 扉をタップ、または見つめる | 扉に触れる、または見つめる |
| 見つめて触れる | 同じ物を1.2秒見つめる | 同じ | 同じ |
「見つめて触れる」は全環境で有効にします。手を使わない人やVRでコントローラーを持たない人も、同じだけ参加できるようにするためです。

### 応え方のルール
1. 必ず応える: 触れられる物は、近づくと縁がかすかに光る。触れると0.1秒以内に光と動きで応える
2. 音は必ず音楽になる: 触れた音は楽曲の調に揃え、次の拍(8分音符)に合わせて鳴らす。誰がどう触れても演奏になる
3. うるさくならない: 同時に鳴る音の数に上限を設け、同じ物は0.3秒以内に再び鳴らない
4. 見どころは邪魔させない: 各部屋の見どころの数秒間は、触れても見どころの演出を止めない。反応は控えめにして重ねる
5. 何もしない人にも音の景色を: 触れられないままの物は、ゴンドラが近づくと自分で小さく鳴る

### 見逃させない工夫
- 見どころの3秒前に、その方向から音を鳴らし、光の粒を流して視線を誘う
- PCとスマートフォンでは、見回しが正面から大きく外れているとき、見どころの直前にカメラがやさしく正面へ戻る(設定でオフにできる)
- VRではカメラを勝手に回さない(酔いの原因になるため)。光の粒と音だけで誘導する

### 隠し要素
- 各部屋に1つ、ひときわ小さな泡が隠れている(全5つ)。触れると特別な和音が鳴る
- 見つけた数に応じて、ライドフォトの額縁が変わる。5つすべて見つけると、虹色の特別な額縁になる
- 見つけた泡は次の乗車でも記録が残る(ブラウザ内に保存)

### 乗車の記録
降車後、ライドフォトと一緒に小さな記録を見せます。触れた数、選んだ扉、描いた星座の数、見つけた小さな泡の数です。点数や順位はつけません。

## ライドとカメラ
ゴンドラは1本のレールに沿って、時間で決まった通りに進みます。動きにはVRでも酔わない厳しい上限を設け、ゴンドラは常に水平を保ちます。

### 動きの上限
| 項目 | 上限 | 理由 |
| 前進の速度 | 普段1.0〜2.0m/s、最大3.0m/s | 景色を眺められる速さに保つ |
| 加速・減速 | 0.5m/s²以下。速度の変化は2秒以上かけて行う | 急な加減速は最も酔いやすい |
| 上下の移動 | 0.6m/s以下 | 落ちる感覚・持ち上がる感覚を抑える |
| 向きの回転(左右) | 15度/秒以下 | 回転は酔いの大きな原因になる |
| 傾き(前後・左右) | なし。常に水平 | 地平線が傾くと酔いやすい |
| 物との最短距離 | 0.5m以上 | VRで物が顔にぶつかる感覚を避ける |
- 万華鏡の間で回っているのは周りの模様であり、ゴンドラは回らない
- 視界の下側には常にゴンドラの縁(泡の下半分の枠と手すり)が見えるようにする。動かない基準が視界にあると、VRでの酔いが大きく減る

### 速度の決め方
- レール上の位置は「経過時間 → レール上の位置」の対応表で決める。楽曲と映像が常に一致する
- 各部屋の入口では減速し、視界が開ける瞬間を少しゆっくり見せる
- 見どころの間は速度を最も遅く(0.5m/s程度)し、ほとんど止まっているように感じさせる

### カメラ(PCとスマートフォン)
- カメラはゴンドラの座席に固定し、見回せる範囲はゴンドラの正面から左右120度、上下60度まで
- 視野角は75度(設定で60〜90度)
- 見回しは「ドラッグで回す」と「マウスの位置に追従」から選べる
- スマートフォンの傾きによる見回しは、最初に許可を求める。断られたらドラッグ操作にする
- ポーズすると、ゴンドラも音楽もその場で止まる

### カメラ(VR)
- 頭の動きをそのまま反映する。カメラを勝手に回したり動かしたりする演出は一切しない
- 座って乗るか、立って乗るかを最初に選ぶ。座席の高さを自動で合わせ、いつでも正面を合わせ直せる
- 移動中は視界の外周をわずかに暗くする(設定で強さを変えられる)

### 快適モード
- 「標準」と「穏やか」の2つを用意する。穏やかでは上下の動きと向きの回転を半分にし、万華鏡の模様の回転を止める
- どちらのモードでも乗車時間は同じ13分。楽曲との同期は崩さない

## UI/UX設計
UIは本物のアトラクションの体験の順序をなぞります。待ち列(読み込み)、入口と切符(ホーム)、乗車前の案内、乗車中は何も出さない、降りたらライドフォト、という流れです。素材は案1と同じくガラスだけで作ります。

### UIの原則
1. アトラクションの作法に従う: 並ぶ、切符を切る、案内を聞く、乗る、写真を受け取る。誰もが知っている順序なので説明が要らない
2. 乗車中は何も出さない: 13分間、画面に固定された表示はゼロ。必要な案内は泡の内側の曇りに書く
3. 素材はガラスだけ: 曇りガラス、透明ガラス、泡の膜、指でなぞった文字
4. すぐ応える: 入力から0.1秒以内に必ず音と動きで反応する
5. すべての環境で同じ体験: PC、スマートフォン、VRで画面の構成は変えても、体験の順序と言葉は同じにする

### 画面ごとの設計
| 画面 | 見た目と動き | 操作 |
| 待ち列(読み込み) | 乗り場へ続く薄暗い通路。読み込みが進むにつれて、両側に並んだガラスの灯りが手前から一つずつ灯る | 全部灯ったら「乗り場へ」が浮かぶ。クリックで進む(ここで音を有効にする) |
| 入口(ホーム) | ガラスのアーチに光でタイトルが書かれ、その下にガラスの切符が浮かぶ。切符には「第3便」のように乗車回数が刻まれる | 主な項目は「乗る」。他に「乗り方(画面 / VR)」「快適モード」「設定」「写真の棚」「クレジット」 |
| 乗車前の案内 | 曇りガラスの立て札に、3つの案内が指で書かれていく:「触れると鳴ります」「見回せます」「酔いやすい方は穏やかモードへ」 | 6秒で自動的に進む。クリックで飛ばせる。2回目以降は出さない |
| 乗車中 | 表示なし。マウスを動かしたときだけ、隅に小さな雫(ポーズ)が2秒間浮かぶ | Esc、雫、画面の長押しでポーズ |
| 乗車中の案内 | 0:20頃に一度だけ、泡の内側の曇りに「触れると、鳴ります」と書かれて消える | ― |
| ポーズ | 泡の内側に息を吹きかけたような曇りが広がり、項目が書かれる。ゴンドラも音楽も止まる | 「続ける / 快適モード / 音量 / 降りる」 |
| ライドフォト | 降車後、天球で撮った写真がガラス玉の中に浮かび、ゆっくり回る。温室と雨の回廊の瞬間も合わせて3枚から選べる | 「保存」「共有」「もう一度乗る」「入口へ」 |
| 乗車の記録 | 写真の下に曇りガラスの小さな札。触れた数、選んだ扉、描いた星座、見つけた小さな泡 | ― |
| 写真の棚 | 過去のライドフォトが小さなガラス玉として棚に並ぶ(最新10枚) | 選ぶと拡大、保存、削除 |
| 設定 | 曇りガラスのパネル。タブは画質 / 見回し / 快適さ / 音 / 表示 | 変更は即時反映 |

### ライドフォトの詳細
- 撮影は自動。天球の見どころ(9:50頃)、温室の花(2:40頃)、雨粒が止まる瞬間(5:10頃)の3か所
- 撮影時に画面の演出が一瞬止まることはない。裏で別の画像として高解像度に描き出す
- 写真には、乗車中に描いた星座、選んだ扉の色、額縁(隠れた泡の数で変わる)が反映される
- 画像には小さく「泡沫回廊・第3便・2026.10.20」のような刻印を入れる
- 保存は横長(1920×1080)と正方形(1080×1080)から選べる。スマートフォンでは端末の共有機能で直接送れる
- 写真はブラウザ内に保存する。容量の都合で最新10枚まで

### VRでのUI
- メニューは手を伸ばした先(約1.2m)に浮かぶ曇りガラスの板として出す
- 選び方は、指さしてトリガー、手で直接触れる、1.2秒見つめるの3通り
- 文字は視野の中で十分な大きさになるよう、画面版の約2倍の大きさで作る
- ライドフォトは手のひらに乗るガラス玉として受け取り、回して眺められる

### 文字と色
- 書体は案1と共通(細めの明朝体＋細身のサンセリフ)
- 色は部屋の光に合わせて変える。入口は夜明け前の青、ライドフォトの画面は夜明けの金
- 最小の文字サイズは1080p基準で18px。スマートフォンでは16px相当以上

### 英語版
- 言語の初期値はブラウザの言語設定で決め、入口の設定からいつでも切り替えられる
- 書体、長い英文に合わせて伸びる札、指でなぞる文字の表現は、案1と共通の部品を使う
- 翻訳の範囲はごく少ない: UI、乗車前の案内3つ、乗車中の案内1つ、乗車の記録、クレジット
- ライドフォトの刻印も英語にする(例: Utakata · Ride No.3 · 2026.10.20)

### アクセシビリティ
- 操作しなくても最後まで体験できる(これ自体が最大の配慮)
- 見つめて触れる時間を0.8 / 1.2 / 2.0秒から選べる
- 光の点滅や強い閃光を抑えるモード(天球の暗転からの点灯、朝日の強さを弱める)
- 文字の大きさを3段階で変更できる
- 音を出せない環境のために、触れた反応は光だけでも分かるようにする
- 正面へ自動で戻る機能のオン/オフ、見回しの方式の切り替え

## トランジション設計
部屋と部屋の境目はすべて「虹色の薄膜を通り抜ける」演出で統一し、これを作品全体の合図にします。画面の遷移も、膜・泡・切符といった世界の中の物の動きとして見せ、黒い画面は使いません。

### 遷移の一覧
| 遷移 | 演出 | 長さ | 実装の方式 |
| 待ち列 → 入口 | 通路の突き当たりのガラス扉が開いて光があふれ、入口のアーチが現れる | 1.5秒 | 通路と入口を一つのシーンに置き、カメラを前進させる |
| 入口 → 乗車前の案内 | 切符に光の穴が開き(改札)、切符が光の粒になって消える。カメラは乗り場へ進む | 1.5秒 | 切符は画面上の要素ではなく3Dの板として作る |
| 乗車 | 水面からゴンドラが浮かび、泡の殻が下から上へ閉じる | 2.0秒 | 殻の閉じ具合を0から1へ動かす。閉じた後は画面の縁に泡越しの効果を常にかける |
| 部屋 → 部屋 | 膜がたわみ、通り抜ける瞬間に視界全体に虹色の縞が走り、後ろで膜が元に戻る | 0.6秒 | 膜は薄膜干渉の材質の板。通過の瞬間だけ画面全体に干渉の縞と歪みをかける |
| 天球の暗転 | 2秒間の暗闇の後、星が一つずつ灯る | 2秒＋点灯 | 唯一の暗闇。演出として扱い、光の点滅を抑えるモードでは点灯をゆっくりにする |
| 乗車中 → ポーズ | 泡の内側が曇り、項目が書かれる。ゴンドラと音楽が止まる | 0.4秒 | 案1と共通の曇りの効果 |
| ポーズ → 乗車中 | 曇りが晴れ、ゴンドラと音楽が同時に動き出す | 0.3秒 | 音楽はポーズした位置から再開する |
| 降車 → ライドフォト | 泡が開き、見上げた空に浮かぶ一つの泡の中に写真が映っていて、それが手元まで降りてくる | 2.5秒 | 写真は撮影済みの画像を泡の材質に貼る |
| ライドフォト → もう一度乗る | 写真の泡が大きくなり、その中へ入ると乗り場に立っている | 2.0秒 | 待ち列と案内を飛ばして乗り場から始める |
| ライドフォト → 入口 | 写真の泡が写真の棚の方へ飛んでいき、入口に戻る | 1.5秒 |  |
| 画面 → VR | 白い霧に包まれ、霧が晴れるとヘッドセットの中で乗り場に立っている | 1.0秒 | VRの開始にはブラウザの規則で一度の操作が必要なので、入口の「VRで乗る」で開始する |

### 遷移のルール
1. 部屋の境目は必ず膜: 膜を通るたびに音が一つ鳴る。膜は「次の場面が来る」という合図として、作品の中で一貫させる
2. 黒い画面を使わない: 例外は天球の暗転だけで、これは演出として設計する
3. 待ち時間を演出の中に隠す: 次の部屋は前の部屋の途中で読み込み終える
4. VRではカメラを演出で動かさない: 入口から乗り場へのような移動は、VRでは白い霧の切り替えに置き換える
5. 動きの曲線と音は案1と共通: ゆっくり始まって粘りながら止まる曲線と、遷移ごとのガラスの音を揃える

部屋ごとに時間帯・色・光・広さを変え、13分の中で一日が過ぎるように見せます。ガラスの種類、角を作らない形、真鍮の細い枠という基本のルールは案1と共通です。

| 雨の回廊 | 雨の昼 | 灰青、街灯りの琥珀 | 曇り空の柔らかい光、にじむ灯り | 小 | 曇り、水の膜、雫形の柱 |

### ゴンドラ(泡)
- 直径約2.4mの透明な球。下半分に真鍮の細い枠と手すり、曇りガラスの座席がある
- 表面には常にゆっくり流れる薄膜の虹色。光の当たり方で色が変わる
- 乗っている間は、視界の縁にだけ泡の内側の反射と虹色をかすかに残す(画面の中央は澄んだまま)

### 見せ方のルール
- カメラの道筋が決まっているので、すべての区間を「どこから見て最も美しいか」で配置する。見えない裏側は作らない
- 各部屋の入口で、最初の一枚絵(視界が開ける構図)を必ず設計する。部屋ごとに絵コンテを1枚描いてから作る
- 光の強い場面(温室の朝日、夜明け)の直前は少し暗くし、明るさの差で驚きを作る
- 色収差やブルームなどの画面効果は、膜を通る瞬間と見どころにだけ強める

## サウンドと音楽
13分の楽曲が、このアトラクションの背骨です。楽曲は作曲せず、ガラスの音とシンセサイザーの音をプログラムで組み立てて演奏します。先に楽曲の構成を作り、映像とゴンドラの動きをその構成に合わせて組み立てます。乗る人が触れた音は、その場の楽曲の調と拍に揃えて鳴らします。

### 楽曲の構成
| 区間 | 楽曲の役割 | 主な音色 | 触れた音 |
| 乗り場 | 静かな序奏。期待を作る | シンセの持続音、遠いガラスの鐘 | 吊られた泡の低い音 |
| 朝露の温室 | 主題(4小節の短い旋律)が初めて現れる | グラスハープ(ワイングラスを擦った録音) | 露の高い音 |
| 雨の回廊 | 主題が小さく、内向きになる。雨が止まると一度ほぼ無音 | 柔らかいピアノ風のシンセ、雨の音 | 雨粒の澄んだ音 |
| 万華鏡の間 | 初めてリズムが入る。金と青で和音の進行と音色が変わる | ガラスを叩いた打楽器、ガラス瓶のマリンバ風の音 | ガラス片の音。拍に合わせてこだまする |
| 星の天球 | 全体の頂点。主題がすべての層で戻る | 弦楽器風と合唱風のシンセの持続音、グラスハープ | 星の音。和音の一部として鳴る |
| 夜明けの岸 | 主題がゆっくり解けていく | シンセの持続音、波の音 | 水面の柔らかい音 |
| 降車〜写真 | 短い終結。入口の音楽につながる | ガラスの鐘 | ― |
- 基本のテンポは72BPM。部屋ごとに調を決め、触れた音はその調の5音(ペンタトニック)のうち、その瞬間の和音に合う音に揃える
- 部屋の境目の膜を通る瞬間に、次の区間の曲へ切り替える。膜を通る音がつなぎ目を隠す

### 映像との同期
- 楽曲の再生位置を時計として使い、ゴンドラの位置と演出のタイミングをすべてそこから決める。映像と音が決してずれない
- 見どころの時刻は楽曲の小節の頭に合わせる(花が開く、雨が止まる、星がつながる)
- ポーズすると楽曲もその位置で止まり、再開すると同じ位置から続く

### 立体音響
- 音は3D空間に置き、ヘッドホンでは方向が分かる立体音響(HRTF)を使う
- 見どころの3秒前の誘導音は、見るべき方向から鳴らす
- 部屋の広さに合わせて残響を変える。回廊は短く乾いた響き、天球は長く深い響き

### 制作方法
- ガラスの実録音(ワイングラス、ガラス瓶、風鈴、ガラスの器)を音程ごとに揃え、案1と音源を共有する。グラスハープの音も、ワイングラスを擦った録音から作る
- 足りない音色(弦楽器風、合唱風の持続音)はシンセサイザーで作る
- 音量は「全体 / 音楽 / 効果音 / 環境音」を別々に調整できる

### 楽曲の組み立て方
作曲した曲を流すのではなく、楽曲の構成をデータとして書き、その場でガラスの音を鳴らして演奏します。構成は固定なので毎回同じ曲として聞こえ、キューシートとは小節の単位で必ず一致します。
- 区間ごとに、調、和音の進行、主題の旋律、重ねる層(持続音、分散和音、旋律、リズム、きらめき)と、その強さの変化を構成データ(JSON)に書く
- テンポは72BPMで固定する。見どころはすべて小節の頭に置き、キューシートの時刻は構成データの小節から自動で計算する
- 演奏はWeb Audio APIで少し先の音まで予約して鳴らし、描画が重い瞬間でも音が遅れないようにする
- 触れた音は、その瞬間の和音に含まれる音から選んで次の拍に鳴らす。構成が分かっているので、乗る人の音が必ず曲に溶け込む
- Blenderのプレビズには、同じ構成データから書き出した13分の音声ファイルを使う
- 構成データと演奏の仕組みはClaudeが作り、通しで聴きながら調整する

### Sunoを使う場合
- 対象は、頂点の星の天球と、余韻の夜明けの岸の2区間だけ。他の区間はプログラムの楽曲で完成させる
- テンポ72BPM、その区間の調、グラスハープと弦楽器中心の編成をプロンプトで指定する。生成した曲の拍の位置を解析し、見どころの時刻を曲の小節に合わせ直す
- 触れた音を曲に揃えるため、Sunoの曲を使う区間でも、構成データにその曲の調と和音の進行を書いておく
- 権利とダウンロードの扱いは案1と同じ。有料プランで生成し、採用する曲だけをダウンロードして、プランと日付の記録を残す

## 技術設計
土台は案1と同じThree.jsとTypeScriptで、ガラスの材質・UIの効果・音の仕組みを共通部品として使います。案2の強みは「カメラの道筋が決まっている」ことで、光の焼き込みと見えない部分の削除を最大限に行い、スマートフォンとVRでも動く軽さを確保します。

### 案1との違い
| 領域 | 案2での扱い |
| 進行の時計 | 楽曲の再生時刻をすべての基準にする。映像・ゴンドラ・演出は時刻から計算する |
| 移動 | 物理エンジンは使わない。レール上の位置を時刻から決める |
| 演出の制御 | 「時刻 → 出来事」の一覧(キューシート)で、花が開く、雨が止まる、撮影するなどを起こす |
| 触れる判定 | 画面やコントローラーからの光線と物との交差判定だけ |
| 対応環境 | スマートフォンとVRを正式に対応する(案1は二次対応) |

### レールとキューシート
- レールはBlenderでカーブとして作り、点の列として書き出す。ゲーム側で滑らかな曲線として補間する
- 時刻とレール上の位置の対応は、Blenderのアニメーション(ゴンドラの空の物体の動き)として作り、書き出して使う
- 演出のきっかけはBlenderのタイムラインマーカーで指定し、スクリプトでキューシート(JSON)に書き出す。Blenderで映像と音を見ながら時刻を決められる
- キューシートの例: 2:40 花が開く、5:10 雨が止まる、5:50 扉が現れる、9:50 星がつながる・撮影

### 描画の工夫
- 焼き込みを最大化: 光と影はすべてライトマップに焼く。動く光源は持たない(星や灯りは発光の材質で表現する)
- 見えない部分を削る: レール上のどこからも見えない面をBlender側で削除する。遠景は板の絵(インポスター)に置き換える
- 部屋ごとの課題と手法:
| 部屋 | 技術的な課題 | 手法 |
| 朝露の温室 | 大量のガラスの植物と露 | 同じ形をまとめて描くインスタンス描画。露の落下は粒子として描く |
| 雨の回廊 | 数千の雨粒が止まり、それぞれ屈折して見える | 雨粒はインスタンス描画。屈折は本物の透過を使わず、環境画像と画面の画像を歪めて読む簡易な表現にする |
| 万華鏡の間 | 鏡の多重反射 | 画面を三角形に折り返す画面効果で表現し、反射の計算はしない |
| 星の天球 | 何層も重なる透明な球の殻(ガラス越しのガラス) | 殻には透過を使わず、縁の反射と薄膜干渉の虹色だけで描く。通り抜ける瞬間の効果で殻の存在を伝える |
| 夜明けの岸 | 水面の反射と屈折 | 平面反射を1回だけ描く。砂のきらめきはシェーダで表現する |

### 読み込み
- 部屋ごとにファイルを分け、今の部屋にいる間に次の部屋を読み込み、2つ前の部屋は解放する
- 初回の読み込みは待ち列と入口と乗り場で10MB以下。各部屋は15MB以下
- 読み込みが間に合わない回線では、部屋の手前の膜の直前でゴンドラをごく自然に減速させて待つ(楽曲は持続音で引き延ばす)

### ライドフォト
- キューシートの撮影の時刻に、同じ場面を画面とは別に高い解像度で描き出す(PCは2560×1440、スマートフォンは1920×1080)
- 額縁と刻印は2Dの画像として合成する
- 保存は画像のダウンロード。スマートフォンでは端末の共有機能で直接送れるようにする
- 写真はブラウザ内のデータベース(IndexedDB)に最新10枚まで保存する。設定と隠れた泡の記録はlocalStorageに置く

### スマートフォン
- 端末の傾きによる見回しは、iOSでは操作をきっかけに許可を求める必要がある。乗車前の案内で許可を求め、断られたらドラッグ操作にする
- 縦持ちと横持ちの両方に対応する。縦持ちでは視野角を広げ、見どころが画面の中央に入るように見回しの初期位置を調整する
- 発熱を抑えるため、描画解像度と1秒あたりの描画回数(30fps)を抑えた専用の品質プリセットを使う

### VR(WebXR)
- 没入型VRのセッション(immersive-vr)を使い、座って乗るか立って乗るかで床の高さの扱いを変える
- 描画の速さはVRで最も厳しく、Meta Quest 3で72fpsを必ず保つ(目標は90fps)。フレームが落ちると酔いの原因になるため、品質より速さを優先する
- WebGPUとVRの連携は、主要なVRヘッドセットのブラウザで2026年時点でまだ実験的な機能。VRではWebGL2の経路で描画する
- Three.jsのWebGPUレンダラーのWebGL2経路でVRが使えるかを技術検証で確かめる。使えない場合は、VR版だけWebGLRendererで描き、共通部品のシェーダを2系統で用意する
- 手はコントローラーとハンドトラッキングの両方に対応する。ハンドトラッキングで作るのは「人差し指の先で触れる」と「メニューを指で押す」の2つだけで、つまむ・掴むなどの操作は作らない。触れる判定は指先(コントローラーでは先端)と物の距離で行う

### 性能の目標
| 環境 | 目標 |
| PC(近年の内蔵GPU) | 1080p・中品質・60fps |
| スマートフォン(近年の中位機) | 30fps以上、専用の品質プリセット |
| VR(Meta Quest 3) | 72fps必須、90fps目標 |
| 1部屋あたりのGPUメモリ | 300MB以下(スマートフォンとVRを考慮) |

## Blenderパイプライン
案2では、Blenderが「作品の設計図」そのものになります。まずBlenderで13分全体の動く下書き(プレビズ)を作り、レール・演出の時刻・カメラの見え方をすべてBlender上で決めてから、ブラウザ用に書き出します。造形・材質・圧縮の基本は案1と共通です。

### 流れ
1. 絵コンテ: 各部屋の「視界が開ける一枚絵」と見どころを1枚ずつ描く(計7枚)
2. プレビズ: 箱や球の仮の形でレールと部屋を組み、仮の楽曲に合わせてEeveeで13分の動画を書き出す。この動画で長さ、速さ、見どころの位置を確かめる
3. 酔いの確認: レール上の速度・加速度・回転の速さをスクリプトで計算し、上限を超える区間を一覧で出す
4. 本番の造形: 案1と同じ方法で丸いガラスの形を作る
5. 見えない部分の削除: レール上の多数の地点から見えるかどうかをスクリプトで判定し、どこからも見えない面を削る
6. 焼き込み: 光と影、光の模様、反射用の環境画像を焼く
7. 書き出し: 部屋ごとのglTF、レールの点列、キューシート(JSON)を書き出す

### プレビズ(動く下書き)
- 部屋の仮の形、レール、ゴンドラの空の物体、カメラを配置する。カメラはゴンドラの座席に固定する
- 仮の楽曲を読み込み、タイムラインで映像と音を合わせながら速度を調整する
- 見どころはタイムラインマーカーで印をつける(マーカーの名前がそのまま出来事の名前になる)
- 動画は部屋ごとに書き出し、通しでも確認する。この段階で「13分が長く感じないか」を判断する

### レールとゴンドラ
- レールはベジェカーブで作る。曲がり具合は回転の上限(15度/秒)を守れる半径にする
- ゴンドラの空の物体をカーブに沿わせ、時刻ごとの位置をアニメーションのキーとして持たせる
- 書き出し時に、レールを一定間隔の点列に変換し、時刻と位置の対応表と一緒にJSONにする

### 見えない部分の削除
- レールを0.5mごとに区切った各地点から、見回せる範囲(左右120度、上下60度)に向けて光線を飛ばし、当たった面に印をつける
- 一度も当たらなかった面を削除する。VRでは頭を動かせるので、座席を中心に半径0.5mの範囲も調べる
- 削除前後の三角形数を報告し、削りすぎていないかを動画で確認する

### 焼き込み
- 光と影はすべて焼き込む(案2は動く光源を持たない)
- 反射用の環境画像は、レール上の各部屋の数か所から撮る。ゲーム側ではゴンドラの位置に応じて近い画像に切り替える
- 遠景の建物や山は、レールから見た方向で板の絵(インポスター)としてレンダリングする

### 書き出すもの
| ファイル | 中身 |
| 部屋ごとのglb(7つ) | 造形、材質、ライトマップ、触れられる物の情報(カスタムプロパティ) |
| rail.json | レールの点列と、時刻と位置の対応表 |
| cues.json | 時刻と出来事の一覧(タイムラインマーカーから生成) |
| 環境画像 | 部屋ごとの反射用画像 |

### 案1との共有
- ガラスの材質のプリセット、真鍮の枠の作り方、命名規則、書き出しと圧縮のスクリプトは共通のライブラリにする

## 開発ロードマップ
公開までの目安は約16週です。最初の2週(M0)は案1と共通の技術検証で、最も重い星の天球をVRで72fpsで動かせるかを先に確かめます。
[EMBED node/f9d56cef-81c0: 開発ロードマップ · 5段階、4つのゲート]
M1のプレビズは、作り込む前に13分全体の長さと起伏を確かめるための工程です。ここで退屈な区間が見つかれば、部屋の順番や長さを変えてから本番の制作に入ります。

## リスクと対策
最大のリスクは、VRとスマートフォンで速さを保てるかと、13分を「眺めるだけ」で飽きさせないかの2つです。前者は技術検証で最も重い天球を先に作って測り、後者はプレビズの段階で通しの動画を人に見せて確かめます。
| リスク | 起きると何が困るか | 対策 | 確認する時期 |
| VRで72fpsを保てない | 酔う。VR版が成立しない | VR専用の品質、焼き込みの最大化、見えない面の削除。天球をM0で先に作って測る | M0 |
| WebGPUレンダラーのWebGL2経路でVRが使えない | 描画の仕組みを2系統持つことになる | M0で確認し、使えなければVR版だけWebGLRendererにする判断をその場で下す | M0 |
| 13分が長く感じる、眺めるだけで飽きる | 途中で閉じられる | プレビズの通し動画を複数人に見せ、退屈な区間を削る。必要なら11分程度に短縮する | M1 |
| 乗り物酔い | 体験が不快になる | 動きの上限の自動検査、視界の下の固定の縁、快適モード、VRでの外周の暗さ | M1 |
| スマートフォンの発熱と電池の消耗 | 途中で重くなる、落ちる | 30fpsの上限、低い描画解像度、部屋ごとの解放 | M2 |
| 何層もの透明な殻(天球)が破綻して見える | 頂点の場面の品質が落ちる | 殻は透過を使わず縁の反射と虹色だけで描く | M0 |
| プログラムで組み立てる楽曲が単調に聞こえる | 頂点の場面が盛り上がらない | 区間ごとに和音の進行と音色を変え、見どころで層と音域を広げる。M1の通しで聴いて判断し、必要なら天球と夜明けをSunoの曲で補う | M1〜M2 |
| 回線が遅く部屋の読み込みが間に合わない | 途中で止まる | 先読み、膜の手前での自然な減速、持続音での引き延ばし | M2 |
| 端末の傾きの許可が拒否される | スマートフォンで見回しにくい | ドラッグ操作への自動切り替え | M1 |

### やらないこと
- ゲームオーバー、点数、順位
- 自分で歩き回る移動
- 音声による案内や台詞
- オンラインでの写真の共有機能(保存と端末の共有機能だけにする)

### 並行して進める方法
- M0の技術検証は1回だけ行い、ガラスの材質ライブラリ、曇りの効果、音の仕組み、描画の3経路(WebGPU・WebGL2・VR)をここで確かめる
- 共通の部品は先に必要になった作品で作り、もう一方のディレクトリへコピーして取り込む。例えばガラスの植物は案2の温室で作り、案1の街で使う
- 規模が小さく遊びの仕組み(パズル)がない案2のほうが、先に公開まで届く見込み。案2で詰めたガラスの見た目と性能の知見を、案1の本編制作に流し込む
- 1人で並行するため、それぞれの期間は単独で進める場合の目安(案2は約16週、案1は約18週)より長くなる

### 決めたこと
| 判断 | 内容 | 理由 |
| 体験時間 | 約13分 | 一度で最後まで見てもらえ、もう一度乗りたくなる長さ |
| 操作 | すべて任意。見回す・触れる・選ぶの3つ | 誰でも完走できるようにするため |
| 進行の時計 | 楽曲の再生時刻 | 映像と音を決してずらさないため |
| 作る順序(この作品の中で) | 楽曲の仮版とプレビズを先に作る | 長さと起伏を、作り込む前に確かめるため |
| 分岐 | 雨の回廊の後に1か所(金と青の万華鏡) | 2回目に乗る理由を最小のコストで作るため |
| VRの描画 | WebGL2の経路 | VRヘッドセットのWebGPU対応がまだ実験段階のため |
| ライドフォト | 自動撮影3か所、保存と端末の共有機能のみ | サーバーを持たずに「持ち帰れる記念」を作るため |
| 公開 | Cloudflareで静的配信 | 案1と同じ運用にするため |
| 進め方 | 案1と並行。別々のディレクトリで開発し、M0の技術検証は2作品で共通 | 共通の部品を一度で作り、2作品で同時に磨くため |
| タイトル | 「泡沫回廊」で確定。英語は「Utakata: A Ride Through Glass」 | 泡のはかなさと、部屋を巡る乗り物であることを両方伝えるため。英語は「うたかた」の響きを残し、内容を副題で伝える |
| 言語 | 日本語と英語を公開時から | 台詞がなく翻訳量がごく少ないうえ、短い体験は海外でも共有されやすいため |
| 夜の便 | 公開時は作らない。公開後の追加の候補 | 全部屋の光の焼き込みと色の調整がやり直しになり、アートの作業量がほぼ倍になるため |
| 楽曲 | 作曲はしない。構成をデータで書き、ガラスの音とシンセサイザーでその場で演奏する。余力があれば天球と夜明けをSunoで補う | 作曲者がいなくても完成させるため。構成を知っているので、映像との同期と、触れた音を曲に溶け込ませることが確実にできる |
| ハンドトラッキング | 指先で触れる、メニューを指で押すの2つだけ。つまむ・掴むは作らない | 体験に必要な操作は「触れる」だけなので、指先と物の距離の判定で足りるため |
